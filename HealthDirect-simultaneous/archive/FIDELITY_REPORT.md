## 2. Architectural Insights

### Two-Channel (Standard)
*   **Strengths:** Simplest to implement; uses a single API connection. Highest raw match count on the most complex sample (`0638.mp3`).
*   **Weaknesses:** Occasional instability in complex multi-speaker segments. In the `4507.mp3` test, it failed to produce a valid output file due to an API timeout/availability issue.

### Parallel Mode A (Centralized Interleaving)
*   **Strengths:** **The most robust architecture.** It was the only approach to successfully process all 6 files without error. Its centralized "Brain" (the Engine) ensures 100% chronological sequence, even when independent workers drift.
*   **Weaknesses:** Higher API quota usage (2 connections per call).

### Parallel Mode B (Distributed Stabilization)
*   **Strengths:** Offloads logic to individual workers, reducing the compute load on the central consumer.
*   **Weaknesses:** Most prone to "Timing Drift" errors. Because workers don't know about each other, it can produce slightly fragmented segments compared to Mode A.

## 3. Key Observations
1.  **Fidelity Ceiling:** Across all approaches, the match count is relatively consistent. This suggests that the current fidelity limit is determined more by the **STT Model (telephony)** and **API parameters (gap/stability)** than the architecture itself.
2.  **Reliability:** The Parallel architecture (splitting stereo into 2 mono streams) proved more resilient to transient API unavailability than the single-stream Two-Channel approach.
3.  **UI Integrity:** Mode A provides the smoothest visual experience. Mode B and Two-Channel occasionally require larger "Reflow" corrections in the terminal to maintain the timeline.

## 4. Tuning for Maximum Fidelity

To achieve results closest to the Golden Set baseline, we recommend the following configuration:

| Parameter | Recommended Value | Reason |
| :--- | :--- | :--- |
| **Architecture** | `Parallel Mode A` | Provides the only 100% reliable chronological interleaving logic. |
| **Stability** (`--stability`) | `1.5s - 2.0s` | Increasing from 1.0s to 1.5s gives the API more time to correct interim text, reducing "flicker" and out-of-order turns in rapid conversations. |
| **Gap** (`--gap`) | `0.3s - 0.4s` | A tighter gap threshold creates more frequent turn splits, which better matches natural human conversational flow. |
| **Model** (`--model`) | `chirp_2` or `chirp_3` | While `telephony` is fast, the Chirp series offers significantly higher word accuracy, which is the current primary bottleneck for fidelity. |

## 5. Final Recommendation
For production environments where conversational integrity is paramount, **Parallel Mode A** is the recommended choice. While **Two-Channel** is efficient for simple calls, **Parallel Mode A**'s centralized interleaving logic handles rapid-fire interjections and overlapping speech with significantly higher stability.
