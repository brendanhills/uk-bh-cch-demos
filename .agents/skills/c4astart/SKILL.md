# C4A Start

## Overview

The `c4astart` skill provides instructions and workflows for uploading
application prototypes to the C4A Starter service. It handles the packaging of
files and the necessary authentication via the `gosso` tool.

## Quick Start

1.  **Prepare your files**: Ensure your application or static files are ready.
2.  **ZIP the content**: The service only accepts ZIP files.
3.  **Download the script**:
    -   First, attempt to clone the CLI from GHES using SSH (recommended): `git
        clone git@depot.code.corp.goog:ace/porcupette-cli.git` (or use HTTPS as
        an alternative: `git clone
        https://depot.code.corp.goog/fog-idp/porcupette-cli`).
    -   **Fallback**: If the clone operation fails despite meeting the
        prerequisites, use the built-in fallback script provided natively with
        this skill at
        `google3/coresystems/developer/coe/idp/skills/c4astart/scripts/upload_zip.py`.
4.  **Run the upload script**: Use `python3 porcupette-cli/upload_zip.py` (or
    `python3 <path_to_fallback>/upload_zip.py`) with the required metadata. This
    returns the `applicationId` of the created application.
5.  **Print a link to C4A Starter**: Output a link to
    `https://start.c4a.corp.goog/applications?focus=<applicationId>`, replacing
    `<applicationId>` with the ID returned in step 4.

## Input Requirements

The provided ZIP file must contain either an NPM application, or a static web
page.

A static web page zip contains a file named `index.html`, and may contain
additional files and resources such as images and JavaScript source files.

The following frameworks are examples of valid NPM applications:

-   React
-   Angular
-   Next.js
-   Glasses Blocks
-   XR Blocks

Applications generated by AI Studio are valid inputs by default. Use this skill
when deploying an AI Studio application.

**Important Note on Ports**: C4A Starter deploys apps to Cloud Run, which
expects the application to expose and listen on **port 8080**. Local development
ports typical in Node or Python apps (like `3000` or `5000`) will not work.
Before deploying, you must validate that the application is configured to use
port 8080 (or respects the `PORT` environment variable), otherwise the
deployment will render a blank or broken page.

### Updating an Existing Application (Post-Initial Upload)

If the user makes more changes to the application after the initial upload, **do
not** repeat steps 1 to 5, as that creates a completely new application in the
C4A Starter system. Instead, update the existing application by pushing changes
to the GitHub Enterprise repository that C4A Starter created for it.

To do this:

1.  **Retrieve the GitHub Repository URL**: Use the `get_application.py` script
    with the `applicationId` (obtained from the initial upload) to fetch the
    application metadata:

    ```bash
    python3 get_application.py <applicationId> [--test-env]
    ```

    This prints a JSON response. Look under `components` for the `githubRepo`
    field (for example,
    `https://depot.code.corp.goog/ai-studio-prototypes-exp/my-test-app`).

2.  **Clone the Repository**: Convert the HTTPS URL into an SSH clone URL and
    clone the repository. For example:

    ```bash
    git clone git@depot.code.corp.goog:ai-studio-prototypes-exp/my-test-app.git
    cd my-test-app
    ```

3.  **Create a New Branch**: Direct pushes to the `main` branch are blocked.
    Create and switch to a new branch:

    ```bash
    git checkout -b <new-branch-name>
    ```

4.  **Apply and Commit Changes**:

    -   *First-time update after clone*: Copy/apply the updated application
        files from your workspace location into the cloned repository directory.
    -   *Subsequent updates*: Make changes directly in the local cloned
        repository files; you do not need to copy files from external
        directories each time.

    Once the changes are ready, stage the files and commit:

    ```bash
    git add .
    git commit -m "<Descriptive commit message>"
    ```

5.  **Push and Open a Pull Request**:

    -   *First-time update after clone*: Push your branch to the remote origin:

        ```bash
        git push -u origin <new-branch-name>
        ```

        The output from the git push command will contain a URL to create the
        Pull Request on GitHub Enterprise, similar to:

        ```text
        remote: Create a pull request for 'test-branch' on GitHub by visiting:
        remote:      https://depot.code.corp.goog/fog-idp/porcupette-fe/pull/new/test-branch
        ```

        Navigate to that URL, click the button to open/create the Pull Request,
        and then approve and merge the created PR.

    -   *Subsequent updates*: Push your changes to the same branch using the
        same `git push -u origin <new-branch-name>` command. Then, visit the
        same Pull Request link to view the updated pull request, and approve and
        merge the PR.

    Merging the Pull Request triggers the GitHub Actions configured in the
    repository to build and deploy the new image to reflect the changes.

## Summary of Commands

```bash
# Basic Upload
python3 upload_zip.py <file.zip> --repo-name <repo> --application-name <app>

# Upload to Test Environment
python3 upload_zip.py <file.zip> --repo-name <repo> --application-name <app> --test-env

# Retrieve Application Metadata
python3 get_application.py <applicationId>

# Retrieve Application Metadata in Test Environment
python3 get_application.py <applicationId> --test-env
```

## Prerequisites & Requirements

-   **GitHub On-Prem (GHES) Account & SSH Keys**: Users MUST have their GHES
    account and SSH keys set up to clone the CLI. Before starting the Quick
    Start, ensure their GHES access is configured. If they run into clone errors
    or lack setup, you MUST run the `github-onprem-setup` skill to automatically
    initialize their workstation. Do not just link to documentation; run the
    skill for them.
-   `python3`
-   `pip install requests`
-   `gosso` tool (installed via `sudo apt install gosso`)
