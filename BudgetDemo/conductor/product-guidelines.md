# Product Guidelines

This document outlines the design, interaction, and development guidelines for the Australian Budget Analysis Dashboard and Data Extraction Tool.

## 1. Design & UX Principles
* **Professional and Minimalist Layout:** The dashboard should look clean and corporate. We will use a professional color palette—deep navy blues, slate grays, and teal accents—rather than default bright colors.
* **Responsive Column Layout:** Use Streamlit's multi-column layout (`st.columns`) to divide content effectively. For example, keep key metrics (GDP growth, nominal GDP) at the top, and separate the visual charts from the interactive AI Chat Assistant.
* **Loading Indicators:** Budget parsing and LLM inference can take time. Always use explicit loading states (e.g., `st.spinner`) to inform the user when the application is busy.
* **Error Handling:** Gracefully catch and display errors (e.g., file not found, API failures) using clear, user-friendly warnings (`st.warning` or `st.error`) rather than raw python tracebacks.

## 2. Data Visualization & Charts
* **Interactive Visualizations:** Use interactive plotting libraries (like Altair or Plotly) rather than static images, allowing users to hover and inspect budget details.
* **Consistent Axes and Labels:** Ensure all charts have properly labeled axes, units (e.g., AUD millions/billions, %), and clear legends.
* **Caching:** Heavy computations (like loading massive Excel sheets or CSVs) must be cached using `st.cache_data` or `st.cache_resource` to keep the UI snappy.

## 3. AI Chat Assistant & Grounding
* **Strict Grounding:** The chat assistant must only answer questions based on the provided PDF budget documents (Budget Paper No. 1 chapters). If information is missing, it should say: *"I cannot find that information in the provided budget documents."* rather than hallucinating.
* **Clear Citations:** Every answer generated by the assistant must show where the information came from (e.g., `bp1_bs-1.pdf, Page 12` or `Budget Paper 1, Statement 3`).
* **Chat History:** Maintain a clean, scrollable chat message history using Streamlit's native chat elements (`st.chat_message`).

## 4. Code & Architecture Patterns
* **Modularity:** Separate the UI/Streamlit layer from the data extraction and AI reasoning layers.
* **Configuration Over Hardcoding:** Store configuration details (like paths to PDF files or model options) in a configuration file or constants module.
