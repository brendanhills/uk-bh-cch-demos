# Project Rules

- **Gemini Live Pre-Warming Keep-Alive Blueprint**: The authoritative pre-warming architecture developed by Gemini Live API engineers (such as `kkrishnan90`'s `prewarmed-gemini-live-voice-assistant`) uses sparse digital silence (`b'\x00'` PCM bytes) streamed at periodic intervals (e.g., 2.5s) to hold WebSocket channels hot. Always implement this as the gold-standard pre-warming keep-alive, but provide an explicit config-driven override (`"enable_prewarming": false` and `--no-prewarm`) to guarantee standard connection fallbacks for varying network or audio hardware conditions.
- **Pytest Keep-Alive & Background Stream Isolation**: Real-time background tasks (such as pre-warming standby loops or active keep-alives) broadcast periodic event frames. Standard mock/integration tests asserting exact sequential JSON sequences will break when these are broadcast asynchronously. Always isolate and bypass background pre-warming standby loops under `pytest` environments (by verifying `if "pytest" in sys.modules:`) unless the test explicitly overrides the bypass to test ping behavior.
- **Zero-Retry Bubble Failure Principle**: Live voice-translation streams must not attempt background reconnection retries on connection reset errors or abnormal websocket closures. Silent retries cause overlapping playhead playbacks, speech synchronization drift, and audio buffer corruption. Always fail immediately: set `is_active = False` on the session coordinator, teardown background streaming tasks, and bubble the exception details straight to the patient and clinician dashboard UI consoles.
- **Dynamic Multilingual Glossary Conformity**: To prevent GCP Translation V3 registration failures, any glossary compiler/exporter (such as `export_to_csv`) must dynamically discover all active language columns present in the source database rather than using hardcoded headers. It must format formal/informal dictionaries into flattened strings and only export entries that have fully-populated, non-empty translation cells across every single header column.
- **Gemini Live Translate Compatibility**: Under developer API mode, `gemini-3.5-live-translate-preview` does not support `system_instruction` when used in tandem with `translation_config`. To avoid WebSocket 1011 crashes, always omit the `system_instruction` parameter in `LiveConnectConfig` for live translation models.
- **Model-Specific Connection Configurations (Translation vs. Multimodal)**: Gemini Live API handles native translation models (e.g., `gemini-3.5-live-translate-preview`) and standard multimodal models (e.g., `gemini-3.1-flash-live-preview`) using completely distinct configuration blocks. Native translation models must configure with `translation_config` (omitting `system_instruction`). Standard/multimodal models must configure with custom `system_instruction` and `speech_config` blocks (omitting `translation_config`). Ensure both single-client `/ws` and multi-client coordinator `run_simultaneous_stream` sessions strictly enforce this segregation to prevent multimodal models from conversational roleplay instead of translating.
- **Robust Glossary Schema Parsing**: Clinical glossary translation values can be flat strings, arrays of strings, or dictionaries (with `.formal` and `.informal` keys). Any function parsing these translations (frontend/backend) must recursively map and join all sub-elements to prevent returning empty strings or throwing TypeErrors.
- **Model Compatibility Limit**: Only select, configure, or use Gemini 3.0 and later models (such as `gemini-3.5-live-translate-preview` or newer) for live translation or bilingual transcription tasks. Do not attempt to fall back to older legacy version families (such as Gemini 2.x, 1.x, etc.) to ensure seamless multi-client audio streaming compatibility.
- **Dynamic WebSocket Audio Pacing**: When streaming real-time PCM audio down Gemini Live WebSocket sessions, the pacing loop's sleep interval must be dynamically calculated and perfectly synchronized with the exact chunk duration (e.g., `chunk_ms / 1000.0` seconds) and the playhead increments. Never use hardcoded static sleep intervals (such as 0.2s or 200ms) that mismatch the actual data slice width, as this causes severe audio choppiness or silent gaps.
- **Unified Pacing and Spacing Consistency**: Do not configure separate or custom pacing/tail-buffer spacing durations (such as shortening or lengthening gaps) for specific language presets or dialogue samples (such as Vietnamese). Keep all presets perfectly aligned with the project-wide standard pacing defaults (e.g., 2.5s tail-silence spacing, 4.5s ceased-audio VAD threshold) to prevent audio overlaps, speech fragmentation, or unexpected dead-air silence gaps.
- **Isolating Slow Tests**: Keep all long-running or high-latency tests (such as full real-time audio stream simulations, live API translation runs, or any test taking > 1 minute) isolated in the `long_tests/` directory. Ensure `pytest.ini` excludes `long_tests` from default test discovery (`norecursedirs`) so that local pytest executions remain fast, lightweight, and focused on rapid unit-level verification.
- **Universal Passive Interpreter Constraints**: When designing system instruction prompts for passive real-time audio translation (such as Gemini 3.1 Flash Live sessions), never restrict passive constraints to language-specific examples (e.g., German) and never let "empathy" instructions conflict with "silent and passive" directives. Always enforce a highly concrete, language-agnostic boundary explicitly forbidding the model from talking back, comforting, reassuring, or answering the speaker, even during crying, direct questioning, or high-urgency medical distress across all language configurations.
- **Robust WebSocket Keepalive Heartbeats**: To prevent active streaming or simulation connections from being closed prematurely by load balancers or network proxies during silent intervals, client-side WebSocket code should implement a continuous keepalive heartbeat ping (e.g., sending a periodic `{ action: "ping" }` message every 5 seconds). The backend route handlers must explicitly catch and swallow these ping actions without state modification or side-effects.
- **Custom Logging Preservation with Uvicorn**: When configuring custom logging configurations (such as standard output streams or file-based loggers) in Python web servers, always invoke `uvicorn.run()` with `log_config=None`. This prevents Uvicorn's internal logging setup from disabling or overriding active custom handlers, guaranteeing stdout logging is preserved.
- **Bilingual Stereo Channel Role Mapping Consistency**: When configuring, documenting, or testing dual-channel audio streams, always preserve standard channel-to-role mappings: Left Channel (Channel 1) represents the Patient (foreign language) and Right Channel (Channel 2) represents the Nurse (English). Do not invert these roles in UI layouts, connection settings, or architectural blueprints to ensure compatibility with pre-existing stereo splitting utilities.
