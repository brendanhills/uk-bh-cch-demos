# Specification: Generalise Synthetic Data Generation

## Objective
The goal of this track is to transition from hard-coded, provider-specific generators to a generalized, metadata-driven framework. This will allow the system to generate realistic synthetic documents (PDFs, CSVs) for any customer or industry vertical using a few high-level prompts and configuration schemas.

## Scope
- **Framework Design:** Create a base class or engine that handles document layout, multi-page flowables, and localization logic independently of the content.
- **Prompt-Driven Templates:** Enable the use of LLM-generated content or structured schemas to populate "rich" sections (like legal T&Cs or FinOps insights).
- **Dynamic Localization:** Parameterize currency, addresses, tax rules, and branding colors.
- **Pluggable Data Sources:** Allow the CSV generators to ingest different schema definitions.

## Requirements
- **Reusability:** The core engine should be usable for non-cloud verticals (e.g., healthcare, retail).
- **Simplicity:** A new demo should be configurable in minutes via a JSON metadata file or a set of prompts.
- **High Fidelity:** Maintain the same level of visual and structural realism achieved in the CSIRO cloud demo.

## Acceptance Criteria
- [ ] A core `SyntheticDataEngine` is implemented that abstracts the `reportlab` and `platypus` complexity.
- [ ] Document types are defined via external configuration/metadata rather than separate Python scripts per provider.
- [ ] A "New Customer" demo can be generated by simply changing a configuration file.
- [ ] The engine supports both canvas-based (Invoices) and flowable-based (Agreements) documents interchangeably.
