# 📓 NotebookLM Enterprise API Sandbox - Step-by-Step Manual Walkthrough

This guide shows you how to **manually try everything step-by-step** using the interactive CLI tool `nblm_api.py`. By running these commands, you can inspect the exact REST requests, JSON payloads, responses, and copy-pasteable `curl` equivalents generated by our SDK client in real-time.

---

## 🚀 Quick Reference: CLI Tool syntax

The `nblm_api.py` tool uses the following structure:
```bash
uv run nblm_api.py [GLOBAL_FLAGS] <COMMAND> [COMMAND_ARGUMENTS]
```
*   `[GLOBAL_FLAGS]`: Use `--mode mock` if you want to run offline (defaults to `live` mode).
*   `<COMMAND>`: One of `create`, `get`, `add-source`, `upload-file`, `share`, `delete`, `list`, or `self-test`.

---

## 🔐 Phase 1: Interactive Live Authorization

Before calling live GCP endpoints, run the automatic interactive authorization script:
```bash
uv run setup_env.py
```
This script will:
1. Automatically retrieve and print your Google Cloud access token.
2. Automatically load/update your `.env` file with the token, your active **GCP Project Number**, your GCP account email, and set the default mode to `live`.

---

## 🎯 Phase 2: Manual Step-by-Step Lifecycle (Live Mode)

Now, let's step through the entire API lifecycle manually. After running each command, **look at the console!** It will pretty-print the exact HTTP headers, payload, response status, and copy-pasteable curl commands.

### 1️⃣ Step 1: Create a Notebook
Run the following command to create a new notebook on Google Cloud:
```bash
uv run nblm_api.py create "My Live Sandbox"
```
**Expected Console Output**:
*   Shows a `POST` request to `https://us-discoveryengine.googleapis.com/v1alpha/.../notebooks`.
*   Shows response status `200` with details of your brand new notebook.
*   **Action**: Copy the **`notebookId`** (e.g., `03e78989-76da-4c45-8b5d-5cb2eeca3ff2`) from the JSON response. You will use it in the next steps!

---

### 2️⃣ Step 2: Retrieve Notebook details
Verify your notebook exists and check your current administrative role on it:
```bash
uv run nblm_api.py get <YOUR_NOTEBOOK_ID>
```
*Replace `<YOUR_NOTEBOOK_ID>` with your copied ID from Step 1.*

**Expected Console Output**:
*   Shows a `GET` request to `https://us-discoveryengine.googleapis.com/v1alpha/.../notebooks/<id>`.
*   Shows response status `200` containing `"title": "My Live Sandbox"`, notebook ID, and metadata roles.

---

### 3️⃣ Step 3: Add a Text or Web Source (Batch Create)
Add documents directly as sources to your notebook. You can do this with either raw text contents or a public URL!

*   **Option A: Add a raw Text Document**:
    ```bash
    uv run nblm_api.py add-source <YOUR_NOTEBOOK_ID> text "Quantum Basics" "Quantum computing is a rapidly-emerging technology that harnesses the laws of quantum mechanics."
    ```
*   **Option B: Add a Web URL Source**:
    ```bash
    uv run nblm_api.py add-source <YOUR_NOTEBOOK_ID> url "Google AI Blog" "https://blog.google"
    ```

**Expected Console Output**:
*   Shows a `POST` request to `/sources:batchCreate` with your payloads formatted inside `userContents`.
*   Shows response status `200` containing the unique `sourceId` for the newly created resource.

---

### 4️⃣ Step 4: Stream Upload a Local File
Upload any local file (e.g., your `.env` or `README.md`) directly as a raw binary stream to NotebookLM!

Let's upload your `README.md` file as a source:
```bash
uv run nblm_api.py upload-file <YOUR_NOTEBOOK_ID> ./README.md "My Readme Guide" "text/markdown"
```

**Expected Console Output**:
*   Shows a `POST` request to `/upload/v1alpha/.../sources:uploadFile` using the raw binary upload protocol.
*   Note the custom headers: `X-Goog-Upload-Protocol: raw` and `X-Goog-Upload-File-Name: My Readme Guide`.
*   Shows response status `200` with the created `sourceId`.

---

### 5️⃣ Step 5: Share Notebook Access
NotebookLM supports granular sharing. Share your notebook with a team member or colleague by assigning them a role:
```bash
uv run nblm_api.py share <YOUR_NOTEBOOK_ID> "sarah.colleague@enterprise.com" "PROJECT_ROLE_WRITER"
```

**Supported Roles**:
*   `PROJECT_ROLE_OWNER`: Full management and deletion rights.
*   `PROJECT_ROLE_WRITER`: Edit, add, and update sources.
*   `PROJECT_ROLE_READER`: Read and query sources.
*   `PROJECT_ROLE_NOT_SHARED`: Revokes access completely.

**Expected Console Output**:
*   Shows a `POST` request to `.../notebooks/<id>:share`.
*   Shows response status `200` verifying the updated access list.

---

### 6️⃣ Step 6: Clean Up (Delete Notebook)
Once you have finished verifying everything, delete the notebook to cleanly remove all sources and resources from your Google Cloud project:
```bash
uv run nblm_api.py delete <YOUR_NOTEBOOK_ID>
```

**Expected Console Output**:
*   Shows a `DELETE` request to `.../notebooks/<id>`.
*   Shows response status `200` with an empty JSON response `{}` indicating successful deletion.

## 🌐 Opening Notebooks in the Web User Interface

After creating or retrieving a notebook, the SDK client will automatically generate and print a **clickable, direct Web UI hyperlink** to open and view the notebook in your browser!

The URL is constructed dynamically to include your active account email (via the `authuser` parameter) and location to bypass browser multi-login Google Account picker interruptions:

```text
https://notebooklm.cloud.google.com/{LOCATION}/?authuser={GCP_ACCOUNT_EMAIL}&project={PROJECT_NUMBER}#notebook={NOTEBOOK_ID}
```

*   `{LOCATION}`: Your configured GCP location (defaults to `us`).
*   `{GCP_ACCOUNT_EMAIL}`: Your active GCP Google Account email address (sourced from `.env` or automatic interactive detection).
*   `{PROJECT_NUMBER}`: Your numeric Google Cloud Project ID.
*   `{NOTEBOOK_ID}`: The UUID of your notebook.

### Example Clickable Console Output:
```text
[SDK SUCCESS] Notebook created successfully! Web UI Link: https://notebooklm.cloud.google.com/us/?authuser=brendan@brendanhills.altostrat.com&project=376231489344#notebook=03e78989-76da-4c45-8b5d-5cb2eeca3ff2
```

You can click this link to open the notebook instantly in your browser under the specified Google Account profile, bypassing any permission-denied or account-picker page redirects!

## 🤖 Phase 3: Dynamic Offline Emulation (Mock Mode)

Want to run everything instantly without incurring any network lag, API quota usage, or GCP billing? Simply change `--mode live` to `--mode mock` in any of the commands:
```bash
uv run nblm_api.py --mode mock create "Offline Notebook"
```
You can use the resulting mock ID to test every single command (`get`, `add-source`, `upload-file`, `share`, `delete`) completely offline!
